`@lonca/n11` covers the n11 seller API as n11 documents it on [developer.n11.com](https://developer.n11.com/documentation/): the REST services (products, price/stock, orders) and the SOAP services n11 still runs for questions, returns, partial cancels, invoice links and catalogue search. You never write XML: SOAP calls go through the same typed client, errors and retries as REST.

:::caution[Unofficial]
`@lonca/n11` is an independent, community-maintained SDK. It is not affiliated with, endorsed by, or supported by n11. "n11" and related names are trademarks of their respective owners.
:::

:::note[0.x]
The package starts at `0.1.0`. Reads are verified against a live seller account, product writes against the test store n11 provides to integrators. Order writes and return decisions are verified up to n11's answer for an order in the wrong state (the test store has no open orders), so their success path relies on n11's documentation. Expect minor releases to adjust shapes as more live traffic is seen.
:::

## Resources at a glance

| `inventory`  |       2 | REST       | Test store                                                   |

| `questions`  |       3 | SOAP       | Live (reads) + test store (answer)                           |
| `claims`     |       8 | SOAP       | Live (reads); test store, failure answers only (decisions)   |
| `shipping`   |       1 | SOAP       | Live                                                         |

## Quick start

```ts
import { createN11Client } from '@lonca/n11';

const client = createN11Client({
  appKey: process.env.N11_APP_KEY!,
  appSecret: process.env.N11_APP_SECRET!,
  env: 'prod', // n11 has no public sandbox
  integratorName: 'MyCompany',
});

const page = await client.products.list({ saleStatus: 'On_Sale', limit: 100 });
for (const p of page.items) {
  console.log(p.stockCode, p.quantity, p.salePrice);
}
```

Keys come from n11 Seller Office (`so.n11.com`). `integratorName` is your company name: n11 needs no registration but logs product writes by it, so send the same value every time, down to letter case and `I`/`ı`.

n11 has no sandbox. For integration tests, ask n11 seller-integration support for a **test store**: it lives on production, and test orders there are real (low-priced) orders.

## Price and stock (async tasks)

Every product write is an asynchronous task. `inventory.updateAndWait` splits the list into tasks of 1000, submits them one after another and waits for each:

```ts
const results = await client.inventory.updateAndWait([
  { stockCode: 'SKU-1', quantity: 12 }, // stock only
  { stockCode: 'SKU-2', salePrice: 149.9, listPrice: 199 }, // price pair
]);
for (const task of results) {
  for (const item of task.items.filter((i) => i.status === 'FAIL')) {
    console.warn(item.stockCode, item.reasons);
  }
}
```

The SDK rejects before sending what n11 would fail anyway: a lone `salePrice` or `listPrice`, more than 2 decimals, `listPrice` below `salePrice`, more than 1000 items per task.

## Creating products

```ts
const attrs = await client.categories.getAttributes('1001012');
// attribute 1 is the brand ("Marka"); every isMandatory attribute is required

const task = await client.products.create([
  {
    stockCode: 'SKU-NEW-1',
    title: 'Örnek Defter',
    description: '<p>…</p>',
    categoryId: '1001012',
    productMainId: 'MODEL-1',
    preparingDay: 3,
    shipmentTemplate: 'Standart', // a template name from Seller Office
    quantity: 10,
    salePrice: 149.9,
    listPrice: 149.9,
    vatRate: 20,
    images: [{ url: 'https://cdn.example.com/defter.jpg', order: 1 }],
    attributes: [{ id: 1, valueId: '2306398' }],
  },
]);

// Create tasks can take from seconds to ~15 minutes.
const result = await client.products.waitForTask(task.taskId, { timeoutMs: 20 * 60_000 });
```

To list against an existing n11 catalogue product, look it up first and pass its `catalogId` or `barcode`:

```ts
const { items } = await client.catalog.search({ barcodes: ['8690000000001'] });
```

## Orders

```ts
import { paginate } from '@lonca/core';
import { normalizeStatus } from '@lonca/n11';

for await (const pkg of paginate((p) => client.orders.list({ ...p, status: 'Created' }))) {
  console.log(pkg.orderNumber, normalizeStatus(pkg.status).normalized);
  const results = await client.orders.approve(pkg.lines.map((l) => l.lineId));
  // per-line results; a line id n11 does not know is left out, so compare with what you sent
}
```

`orders.list` takes a `Date` or epoch ms for `startDate` / `endDate` (n11 clamps the window to 15 days). Set `orderByField: true` to filter by last update instead of creation.

Other order operations: `splitPackage`, `splitPackageByQuantity` (n11 enables it per store on request), `createCollectionRequest` (Horoz / Ceva / Borusan pick-up), `updateLaborCosts` (jewellery), `cancelItem` (partial cancel of an approved line) and `sendInvoiceLink`.

### Cargo labels

n11 has no label service: you cannot download a PDF or ZPL label over the API (n11, 2026-10-14: not planned for now). The label is the package's campaign code, `pkg.cargoTrackingNumber`, printed as a CODE-128 barcode. Render it with any barcode library, or print the label from Seller Office.

## Questions and returns

```ts
const open = await client.questions.list({
  status: 'OPEN',
  startDate: new Date(Date.now() - 7 * 86_400_000),
  endDate: new Date(),
});
for (const q of open.items) {
  await client.questions.answer(q.id, 'Merhaba, ürün yarın kargoda.');
}

const reasons = await client.claims.getReturnDenyReasons();
await client.claims.denyReturn({
  claimReturnId: '27000001',
  denyReasonId: reasons[0]!.id,
  note: 'Ürün kullanılmış olarak ulaştı.',
});
```

`questions.list` is limited by n11 to one call per minute; the client enforces it.

## Errors and limits

Errors are the shared `@lonca/core` classes. n11 reports many client mistakes with HTTP 500 (`TASK_ERR_*` on product tasks, Java exception names on queries) or HTTP 200 (SOAP `result.status: failure`); the SDK maps them to `ValidationError`, `NotFoundError` or `AuthError` so they are not retried as server errors.

n11 sends no `429`. Clients that fire requests milliseconds apart get their IP suspended, so keep bulk work sequential (as `updateAndWait` does) or inject a `TokenBucketRateLimiter` into a resource. Product creation is capped at 10,000 products per hour per store.

## Testing

```ts
import { createFakeN11Client } from '@lonca/n11/testing';

const client = createFakeN11Client({
  handler: (req) =>
    req.path === '/ms/product-query'
      ? { content: [{ n11ProductId: 1, stockCode: 'SKU-1', title: 'Örnek' }] }
      : undefined,
});
```

The fake runs the real client over an in-memory `fetch`: REST handlers return JSON, SOAP handlers (matched by `req.soapOperation`) return the inner XML of the response.
